prose-pre:rounded-md [&amp;_table]:!border-[color:var(--border)] [&amp;_th]:!border-[color:var(--border)] [&amp;_td]:!border-[color:var(--border)]"><h1>Core Web Vitals optimization</h1>
<p>Targeted optimization for the three Core Web Vitals using field data to identify user impact and browser traces to diagnose causes.</p>
<h2>Measure before optimizing</h2>
<p>When a runnable URL is available, read <a href="https://github.com/addyosmani/web-quality-skills/blob/HEAD/skills/core-web-vitals/../performance/references/MEASUREMENT.md" target="_blank" rel="ugc nofollow noopener">the performance measurement workflow</a>. Prefer this sequence:</p>
<ol>
<li>Check page-level CrUX p75 data, with a clearly labeled origin fallback when page data is unavailable.</li>
<li>Record a browser performance trace under stated conditions. With Chrome DevTools MCP, trace summaries can include CrUX alongside the observed lab metrics.</li>
<li>Analyze only the insights associated with the failing metric, then inspect the implicated code and resources.</li>
<li>Re-run equivalent lab measurements after the fix. Do not claim an immediate field improvement; CrUX and first-party RUM need new user visits.</li>
</ol>
<p>If only source code is available, identify likely causes but do not claim that LCP, INP, or CLS is failing without runtime evidence.</p>
